Módulo 1: Consultas en SQL

Es la instrucción fundamental para recuperar datos. Su formato básico es SELECT | FROM | [WHERE].

Orden de Ejecución Lógico de una Consulta

  1. FROM: Obtiene el conjunto de datos inicial de las tablas.
  2. WHERE: Filtra las filas de forma individual.
  3. GROUP BY: Agrupa las filas resultantes en conjuntos.
  4. HAVING: Filtra los grupos que no cumplen una condición.
  5. SELECT: Proyecta (selecciona) las columnas finales.
  6. ORDER BY: Ordena el conjunto de resultados final.
  7. LIMIT / OFFSET: Restringe el número de filas devueltas.

Cláusulas y Operadores Clave

  • DISTINCT: Elimina filas duplicadas del resultado final.
  • LIKE: Busca patrones en texto (comodines: % y _).
  • BETWEEN: Define un rango inclusivo (a >= x AND a <= y).
  • IS NULL / IS NOT NULL: Es la única forma correcta de comprobar valores nulos. Una comparación como columna = NULL siempre evalúa a "desconocido" (falso).
  • Funciones de Agregación: COUNT(), SUM(), AVG(), MAX(), MIN(). Ignoran los valores NULL por defecto, a menos que se use COUNT(*) o la función COALESCE(columna, valor_reemplazo) para sustituir los nulos.

Joins y Subconsultas

  • Joins: Combinan filas de dos o más tablas.
    • INNER JOIN: Devuelve solo las filas que tienen correspondencia en ambas tablas.
    • OUTER JOIN (LEFT, RIGHT, FULL): Devuelven todas las filas de una tabla (o ambas para FULL) incluso si no hay correspondencia en la otra, rellenando con NULL los campos faltantes.
  • Subconsultas: Una consulta anidada dentro de otra. Pueden devolver una sola fila (single-row) o múltiples filas (multiple-row).
    • Operadores para Múltiples Filas: IN (igual a cualquier valor de la lista), ANY (compara con al menos un valor), ALL (compara con todos los valores), EXISTS (verifica si la subconsulta devuelve al menos una fila).

Operadores de Conjuntos

Combinan los resultados de dos o más consultas SELECT.

  • UNION: Combina los resultados y elimina duplicados. UNION ALL los combina sin eliminar duplicados.
  • INTERSECT: Devuelve solo las filas que aparecen en ambos resultados.
  • EXCEPT: Devuelve las filas del primer resultado que no están en el segundo.

Información Adicional Clave

Buenas Prácticas en SQL:

  • Evita SELECT * en producción: Selecciona explícitamente solo las columnas que necesitas. Mejora el rendimiento y hace el código más legible y robusto ante cambios en las tablas.
  • Usa alias de tabla: En consultas con `JOINs`, usa alias cortos y consistentes (ej: `FROM Empleados e JOIN Departamentos d`) para mejorar la legibilidad.
  • Prefiere JOIN explícito: La sintaxis FROM TablaA, TablaB WHERE TablaA.id = TablaB.id es antigua. Usa siempre FROM TablaA INNER JOIN TablaB ON TablaA.id = TablaB.id. Es más claro y menos propenso a errores.
  • Indexación: Asegúrate de tener índices en las columnas usadas frecuentemente en cláusulas `WHERE`, `JOIN` y `ORDER BY` para acelerar las consultas.
