Bases de datos NoSQL y MongoDB

Ejercicio 1

Considere la siguiente representación documental de clientes y pedidos. Analice cuándo conviene embeber la información del cliente dentro del documento de pedido y cuándo es mejor referenciarla por identificador.


{
  "_id": 101,
  "cliente": { "nombre": "Ana", "localidad": "La Plata" },
  "fecha": "2025-05-20",
  "productos": [
    { "sku": "A12", "cantidad": 2 },
    { "sku": "B07", "cantidad": 1 }
  ]
}

a) ¿Qué ventajas tiene el modelo embebido para consultas frecuentes con datos del cliente?

b) ¿Qué problema aparece si el documento cambia con frecuencia o si el cliente se actualiza en muchas operaciones?

c) ¿Cuándo preferiría una referencia en vez de un documento embebido?

Ejercicio 2

En una colección ventas, se almacenan documentos con los campos clienteId, monto, categoria y fecha.


db.ventas.find({
  categoria: "electronica",
  monto: { $gte: 50000 },
  fecha: { $gte: ISODate("2025-01-01") }
}).sort({ monto: -1 })

a) ¿Qué patrón de consulta está representado?

b) ¿Qué tipo de índice sería útil para esta consulta?

c) ¿Qué ventaja tiene filtrar con $match antes de realizar una etapa de agrupación o unión?

Ejercicio 3

Considere una colección usuarios con documentos que tienen campos como nombre, edad, rol y puntos. Analice el siguiente agregado.


db.usuarios.aggregate([
  { $match: { rol: "editor" } },
  { $group: { _id: "$rol", total: { $sum: "$puntos" }, promedio: { $avg: "$puntos" } } }
])

a) ¿Qué hace la etapa $match?

b) ¿Qué sentido tiene la agrupación por rol?

c) ¿Qué diferencia conceptual hay entre este enfoque y una consulta SQL con GROUP BY?
